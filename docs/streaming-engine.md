# Streaming Engine

GeoQC 1.0 processes large geospatial datasets as bounded Arrow record batches.
It does not build a dataset-wide `GeoDataFrame`, so peak working memory is
primarily controlled by the configured chunk size and collector retention.

## Processing pipeline

```text
DatasetSource -> ReaderRegistry -> ChunkReader -> ChunkIterator
              -> ChunkProcessor -> ResultCollector -> StreamingResult
```

- **Reader registry** selects an adapter without coupling orchestration to a
  file format. Register another `ChunkReader` to add a format.
- **Reader** inspects metadata and yields `FeatureChunk` values. Pyogrio reads
  GeoPackage, Shapefile, and GeoJSON through GDAL's Arrow interface;
  PyArrow scans GeoParquet row groups/batches.
- **Iterator** enforces positive, contiguous offsets and normalizes memory
  failures. It never retains previous chunks.
- **Processor** converts a chunk to a partial result. `RuleChunkProcessor`
  passes each chunk to the existing `RuleEngine`; `GeometryChunkProcessor`
  preserves the existing HTTP geometry audit semantics.
- **Collector** merges partial results deterministically. Geometry findings are
  bounded while aggregate counts remain exact.
- **Engine** coordinates inspection, optional CRS enforcement, empty-layer
  detection, processing, and finalization.

The stable API response is unchanged: feature indexes remain zero-based and in
source order, issue types/messages are generated by the same geometry
validator, and findings truncation behaves as before.

## Supported formats

| Format | Adapter | Streaming mechanism |
| --- | --- | --- |
| GeoPackage | `PyogrioChunkReader` | GDAL Arrow stream |
| Shapefile | `PyogrioChunkReader` | GDAL Arrow stream |
| GeoJSON | `PyogrioChunkReader` | GDAL Arrow stream |
| GeoParquet | `GeoParquetChunkReader` | PyArrow batch scanner |

`ReaderRegistry.register()` is the extension point. A reader must implement
`supports`, `inspect`, and `iter_chunks`; application code needs no change.

## Failure model

Adapters translate implementation failures into stable streaming exceptions:

- corrupt or unreadable datasets: `CorruptDatasetError`
- missing required CRS: `MissingCRSError` (enable `require_crs=True`)
- empty layers: `EmptyLayerError`
- invalid geometries: audit findings, not fatal reader failures
- text decoding failures: `DatasetEncodingError`
- allocation failures: `StreamingMemoryError`

The web API intentionally maps reader failures to its existing generic HTTP
422 contract, preventing internal paths or GDAL diagnostics from leaking.

## Configuration and memory

`StreamingConfig.chunk_size` defaults to 65,536 features. Smaller values reduce
peak memory at the cost of more dispatch overhead. The web endpoint uses 16,384
features and retains at most 1,000 detailed findings while counting every
issue. Processors and collectors must not store raw chunks.

## Tests and benchmark

Unit tests use reader/processor/collector test doubles. Integration tests write
and stream all four required formats with a two-feature chunk size, including a
legacy-result parity case.

Run the manual benchmark against a representative dataset:

```bash
uv run python benchmarks/streaming_geometry.py data/large.gpkg --chunk-size 65536
```

It reports wall time and peak Python allocations for full-frame and streaming
geometry validation. For production profiling, also measure process RSS because
GDAL/Arrow native allocations are outside `tracemalloc`.
